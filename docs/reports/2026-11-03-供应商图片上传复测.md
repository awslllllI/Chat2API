# 供应商图片上传复测

日期：2026-11-03  
测试照片：`%USERPROFILE%\Pictures\iOS\IMG_0048.PNG`（约 73KB）  
方式：本地代理 `http://127.0.0.1:8082` → 多模态 chat（含上传/解析等待）

## 结果

| 供应商 | 结果 | 说明 |
| --- | --- | --- |
| DeepSeek | **通过** | `upload_file` + `ref_file_ids`，模型正确描述登录界面截图（约 6–8s） |
| Kimi | **通过** | 原生上传 + 解析等待后提问成功 |
| GLM | **通过** | 修复挂载：`type=image` + `source_id`（不再用 OpenAI `image_url` 塞 data URL） |
| MiniMax | 失败 | 签名已对齐网页盐值，`uploads/prepare` + OSS 204 成功；`send_msg` 仍报 `attachment requires one owned object_key or allowed legacy URL`（对象键归属校验） |
| Qwen 国内 | 失败 | `chat-side.qianwen.com/api/v2/files/getstsToken` 接口存在，但对当前 ticket 返回 `NOT_LOGIN`（chat2-api 会话校验可通过，文件域未接受同一 cookie） |
| MiMo | 失败 | 上游 401；账号「校验」此前只检查字段是否存在。已改为真实请求 `genUploadInfo`，失效凭证会明确提示重新登录 |

## 本次代码修复

- MiniMax：`x-signature` 改为网页盐 `I*7Cf%WZ#S&%1RlZJ&C2`；CN 域名 `agent.minimax.cn` + `region=cn`；OSS 按浏览器 FormData/Blob 上传
- GLM：图片按网页 `source_id` 挂载
- Qwen：STS 优先 `chat-side`，解析走同一 host；`NOT_LOGIN` 给出明确中文错误
- MiMo：OAuth / checker 改为真实上游校验
