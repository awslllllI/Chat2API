# Qwen / dsh 工具轮失败修复

> 日期：2026-10-27  
> 证据：`session-dbd47cea-…/session.v4.jsonl`（Qwen3.7-Max + chat2api）

## 根因

1. **参数类型**：模型把 `todo_write.todos` 写成字符串；dsh 校验要求 array。  
2. **429 风暴**：HCE 回合间距正确返回 429 + `retry_after`≈14–19s，但 dsh 对 `RATE_LIMIT` **秒级连重试**，耗尽后 turn 失败。

## 修复（Chat2API）

| 项 | 做法 |
| --- | --- |
| Schema 纠偏 | `argumentGuard`：string→array/object/number/boolean；单 object→`[object]` |
| Prompt | 工具列表标明 `Arg types`；强调禁止 stringify array/object |
| 准入等待 | 包络未到点且等待 ≤ `retryAfterCapMs`（约 60s）时，代理内 sleep 再选号/acquire；客户端看到慢成功而非 429 |
| 硬 429 | 仍用于真无号、paused、日限、等待超过 cap |

HCE 默认数字未放宽。

## 预期体验

- 工具多轮：可能首包延迟数十秒，但不应再出现「每秒一串 429」。  
- 可 parse 的 stringified `todos`：发出的 `tool_calls.arguments` 为真正 array。  
- 残缺到无法 parse 的参数仍可能被客户端拒绝（靠 prompt + 模型自纠）。

## 三次复盘（session-53d8dc48）

多轮工具已基本可用（todo/write/read/edit 成功），第 8 步挂掉：

1. Chat2API 在上游 socket `close` 时只发 `[DONE]`、**不发 `finish_reason`** → dsh `TRANSPORT: Stream ended without finish_reason`  
2. dsh 连重试 5 次（每次仍吃 HCE 等待）→ 最终 `429 no_available_account`  
3. 仍有 `2API|parameter...` 正文泄漏 → 清理规则已覆盖 parameter/invoke  

修复：Qwen `finalizeClientStream()` 在所有结束路径（complete / close / end / error / zstd）保证先 `finish_reason` 再 `[DONE]`。
