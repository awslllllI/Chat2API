# 账号限流与防风控（W 里程碑）实施报告

> 日期：2026-10-26  
> 范围：Chat2API 本地代理调度层（同供应商多账号）  
> 目标：少封号 —— 事前节流 + 同供应商换号 + 风控/禁言后停号；满号立即 429

## 1. 做了什么

### 事前门闸

- 账号字段：`requestsPerMinute`、`minIntervalMs`、`maxConcurrency`（另保留 `dailyLimit`）
- 内存门闸：`accountGate`（滑动窗 RPM、最小间隔、并发）
- 选号过滤：非 `active`、冷却中、`paused`、超日限、门闸拒绝 → 不可选
- **仅同供应商换号**；不会静默跨到其它厂商
- 同供应商全不可用 → **HTTP 429** + `Retry-After`（1–15 秒封顶，避免客户端超时连发）

### 事后识别（最小集）

- `upstreamErrorClassifier`：`rate_limit` / `ban_or_mute` / `challenge` / `auth` / `empty_success` / `other`
- 禁言/验证码 → 账号 `paused`（需手动恢复）
- 429/限流文案 → 冷却
- **模糊 403 不当成 401/auth**，降低误伤登录态
- 非流式空助手内容 → 不计「健康成功」（对准空回复假成功）

### 默认值（偏宽松、可关）

| 供应商 | RPM | 最小间隔 | 并发 |
| --- | --- | --- | --- |
| DeepSeek | 24 | 1500ms | 1 |
| Kimi | 30 | 1000ms | 1 |
| 其它 Web | 约 12–30 | 1–3s | 1 |

- 新账号创建时写入上述默认
- 字段填 **0** = 该项不限制
- 已有账号未写字段时运行时用供应商软默认（不强制改写磁盘）

### UI

- 添加/编辑账号可改 RPM、间隔、并发
- 账号状态增加 `paused`；详情页可「恢复账号」
- 负载均衡文案改为「同供应商多账号」

## 3. 自测

- 已跑：`node scripts/test-account-gate.mjs`（门闸算术 + 分类规则冒烟）
- **未代替实号冒烟**：本环境无用户 DeepSeek/Kimi 凭证；请用多轮 Tool Calling 任务验证：
  1. 单号人为调低 RPM → 超额得 429 或换到同供应商第二号
  2. 双号其一 paused → 落到另一号且不跨供应商
  3. 两号皆不可用 → 429 且 `Retry-After` ≤ 15s

## 5. 使用提示

1. 重启应用后新逻辑生效；新加账号会带默认限流。  
2. Agent/客户端应对 **429 + Retry-After** 做短退避，勿无限重试。  
3. 出现「已暂停」时到账号详情点恢复，并检查是否真被网页禁言。
