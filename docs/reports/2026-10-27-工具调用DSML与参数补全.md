# 工具调用：DSML 泄漏 / 残缺 CHAT2API / 必填参数补全

> 日期：2026-10-26 / 2026-10-27  
> 范围：Chat2API managed tool-calling（DeepSeek 网页协议桥）  
> 触发：dsh 会话出现原始 DSML、`|CHAT2API|invoke`、`｜end of sentence｜>`，以及 `pwsh` 缺 `description` 导致 `INVALID_ARGS`

## 1. 问题

Managed 文本工具桥把 OpenAI `tools` 注成 Chat2API XML；DeepSeek 网页模型偶发：

1. 输出 **DSML** 特殊标记块而非 Chat2API XML → 客户端当正文泄漏  
2. 输出 **缺 `<` 的残缺 CHAT2API** → 解析失败并泄漏  
3. 带上 **`｜end of sentence｜>`** 等控制 token  
4. 漏填 schema **required**（如 `pwsh.description`）→ 客户端 `INVALID_ARGS`

同供应商换号（d1/d2）**保持不变**。

## 2. 修复

| 点 | 做法 |
| --- | --- |
| DSML | 新增 `deepseek_dsml` 解析器；`managed_xml` 优先，失败静默 fallback |
| 流式 | `ToolStreamParser` 同时监视 XML + DSML 起始；工具块后抑制残渣正文 |
| 残缺 CHAT2API | 容忍 `|CHAT2API|invoke...`（无前导 `<`）并解析为 tool_calls |
| 控制 token | `sanitizeAssistantText` 剥离 end-of-sentence / 破碎标记 |
| 必填参数 | `argumentGuard`：缺 `description` 且有 `command` 时自动补短描述；prompt 标明 REQUIRED |
| Prompt | managed XML 规则强调必填、完整尖括号、禁止控制 token |

**刻意不做**：官方 API 原生 tools 对等；跨协议把 bracket 误解析成 XML（保留协议选择语义）。

## 5. 使用提示

1. 重启应用后主进程解析逻辑生效。  
2. Agent 侧仍应对 `tool_calls` 走标准 OpenAI 循环；若仍见 DSML 正文，把原始 chunk 贴回来。  
3. `description` 自动补全是兜底，模型仍应被 prompt 要求填齐 required。  
4. DeepSeek 账号需重新登录后再用同脚本复测（`CHAT2API_MODEL=deepseek-v4-flash`）。
