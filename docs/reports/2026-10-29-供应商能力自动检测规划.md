# 供应商能力自动检测与适配（规划）

日期：2026-10-29

## 背景

各网页供应商会动态调整：

- 可选模型 / 场景（忙时只开「快速」）
- 思考强度、速度、上下文档位
- 文件/图片上传协议

硬编码模型列表会落后于官网。需要按供应商接入「探测 → 映射 → 落库」管线。

## Kimi 现状（已逆向）

| 能力 | 网页接口 | 说明 |
| --- | --- | --- |
| 模型目录 | `getAvailableModels({ scene })` | 返回 `availableModels` / `moreModels`，含 `reasoningEffortOptions` / `speedOptions` / `contextLengthOptions`、忙闲态 |
| 思考强度 | `options.reasoning_effort` | `NONE…MAX`；UI「标准/进阶」≈ `MEDIUM` / `HIGH` |
| 速度 | `options.speed` | `STANDARD` / `FAST` / `MAX`；当前常见「快速模型」= `SPEED_FAST` |
| 场景 | `scenario` | `CHAT`（plain-chat）、`K3`、`OK_COMPUTER` 等 |
| 上传 | `POST /apiv2-files/file/upload` + `GetFileParseProgress` | 已正面适配，Chat `blocks[].file` |

当前产品默认仍暴露 `Kimi-K2.6`（快速路径）。思考强度通过请求参数 `reasoning_effort`（或模型名含 think）映射，不另造不可用的占位模型。

## 通用管线（拟）

1. **Probe**：登录态下调用供应商「可用模型 / 能力」接口（Kimi: `getAvailableModels`；其它供应商各自 HAR）。
2. **Normalize**：归一成内部 schema：`{ id, displayName, scenario, modalities, options[], availability }`。
3. **Map**：生成 OpenAI 侧 `supportedModels` + `modelMappings` + feature aliases（think/search/speed）。
4. **Persist**：写入 provider 配置（可覆盖用户自定义；内置默认可一键重置）。
5. **Schedule**：启动时 / 手动刷新 / 可选定时；失败保留上次成功快照。

## 分阶段

| 阶段 | 内容 |
| --- | --- |
| P0 | Kimi 原生上传（已完成）；思考强度参数映射（已完成） |
| P1 | Kimi `getAvailableModels` 探测 + UI「刷新模型」 |
| P2 | DeepSeek / GLM / Qwen 等同构探测 |
| P3 | 上传能力指纹（是否支持 image/file、解析状态机）纳入探测报告 |

## 验收

- 官网只剩快速模型时，代理列表与官网一致且不出现不可用模型误导。
- `reasoning_effort=standard|high`（或中文 标准/进阶）能打到对应 enum。
- 图片走原生 upload，不再 base64 进 prompt。
